# Restoration decisions

Every choice made in the restoration: what was kept as NMS left it, what was changed, the evidence for each change and the reasoning. The [README](../README.md) has the overview.

Where a choice could not be settled from NMS's files, the owner of this restoration made it. Those entries are marked **Owner's decision**, with the inference behind them.

## The rule

> Restore as much as we can. The most important thing is that we don't invent anything: we only follow and act on the information already in these files.

**Owner's decision, 2026-11-14:** "do whatever the DOS or Saturn version do; if none of them has the feature, then ask me." (He gave it after seeing the frames of the chain shot and of the impact pictures, which both follow the PC version.) Where a version has the feature, the restoration does what it does; where none has it, the question goes to the owner.

Every change to the games' behaviour traces to something in NMS's files: their code, data, file names, comments and notes, or a later version of the same game (the Saturn port, the DOS branch of the shared source). Where the files leave a gap, the gap is documented and left open, not filled with a plausible guess.

Each change in the code carries a `RESTORE:` comment, and its commit message gives the evidence. Kinds of change:
- **Bug fix:** NMS's intent is clear from their own code, and the code fails at it.
- **Completion:** NMS started something and their files define how it ends.
- **Platform:** needed to run on a retail PS1 instead of a 1996 dev kit, without changing what the game does.
- **New work:** written for the restoration. Kept optional and labelled.
- **Owner's decision:** the files suggest an answer but don't settle it.

| Sony's Psy-Q libraries replaced by a clean-room layer (`psyq/`) on PSoXide | Platform | The games call Psy-Q. Reimplementing those calls from how NMS's code uses them, from documented hardware behaviour and from the 1996 builds' observed behaviour keeps NMS's code intact and the repository free of Sony code. No third-party SDK is used. |
| The layer's VBlank and DMA interrupt work is a hook and a handler of the SDK's dispatcher; the layer has no exception wrapper, vector write, COP0 code or 8 KB stack of its own | Platform | Standard: the SDK has one interrupt dispatcher (`sdk/docs/INTERRUPTS.md`, `sdk/docs/GATE.md` rule 3). Before, `psyq/src/kernel.rs` wrote its own wrapper into the exception vector (assembly with `mfc0`, its own 8,192 byte stack) in front of psx-rt's handler, and took VBlank and DMA there. Now `vblank_hook` is registered with `psx_rt::dispatch::on_vblank` (poll port 1 into the `InitPAD` buffer, the `RCntCNT3` events, `VSyncCallback`, as before) and `DrawSyncCallback` attaches `dma_handler` as the dispatcher's DMA source (it acknowledges DICR and `I_STAT` itself, through `psx_io`). The pad is read with `psx_pad::Controllers::digital()` instead of the deprecated `poll_port1`: the same poll on the wire, no handshake. Stack: the dispatcher gives a handler 400 bytes. The old wrapper's stack was measured first (a probe build painting it; 360X Mission 1 route): VBlank path 908 bytes, DMA path 172, pad poll 144 (QD Up: 128 and 128). The 908 was `SsSeqCalledTbyT` (the 360X sound tick, `UpdateTheSound` in `VblCallback`): its note-on copied a whole song and a whole bank onto the stack (a 784 byte frame). `note_on` now reads only the fields it needs (a separate commit, same arithmetic). The depths after, the sizes and the poll cost are in the row "The layer's size change over the whole work". `psx-gate.toml` loses `cop0-asm`, `deprecated-use`, `vector-write`, and `register-literal` in `gpu.rs` and `kernel.rs`. |
| The sound driver reads a voice's envelope level through the SDK's SPU register names | Platform | `envelope` (`snd.rs`) read the voice's ADSR level register by a literal address (`0x1F80_1C0C + 16 n`); it is `psx_hw::spu::voice::base(n) + voice::ADSR_LEVEL` read with `psx_io::read_u16`, the same address and the same 16-bit read. The last `register-literal` entry of `psx-gate.toml` is gone. Registers the SDK has no accessor for, only an address constant: `DICR` (`psx_hw::dma::DICR`, DMA interrupt control: the GPU channel's interrupt enable and flag, read and written by `DrawSyncCallback` and the DMA handler in `gpu.rs` through `psx_io::read_u32` and `write_u32`). ## 360X's missions in detail

The July 1996 code has no mission-complete logic: `levelcompleted` is never set, so the end-of-mission status screen (`Exit_Level`) is never reached, and a mission ends only when the craft is destroyed (the shields drop only while L1 is held, which is also the weapon-down button, `PANEL.C:112-120`, and by creature contact, below) or Quit is chosen on the pause menu. The game then goes to the high score entry and the title. No NMS source defines the condition (the PS1 July tree, the March trees, the PC version in `SOURCE/MAKEBACK`, the Saturn port). The briefings state each mission's objectives and the status screen has placeholder lines (survivors, rescued, shots fired, shots on target, "OVERALL STATUS : POOPED"), but nothing counts them. As new work (the owner's decision, marked `RESTORE: NEW WORK` in the code), a mission now completes when every shootable creature it placed is destroyed. NMS's path then shows the status screen, with the number of shots fired filled in and the other lines left as NMS's placeholders, and loads the same mission again (only the planet select changes the mission). Shots can now destroy creatures, which is also new work. NMS's own hit test (`process_collisions` in `FIRE.C`, under `#if 0` in July 1996) runs again with the PS1 frame sizes in place of the PC's sprite data, a creature takes as many hits as its map entry's hit points (at least one), and then the creature's own July 1996 logic decides what the hit does (see Creature logic below). Some die and burst like a missile on a wall; some only react. Which creatures are shootable follows NMS's 12 June name list first and the Saturn port's attribute file for the rest (see the shootable rows above). The status screen also shows the shots on target. Completion counts only the shootable creatures that are drawn and whose logic can die; every mission has some now, Mission 6 included. A test build (`X360_CFLAGS=-DX360_TEST_COMPLETE=N`) still clears the creatures after N game frames. Every mission is chosen on the planet select (Left and Right, nine planets). That is the restoration's way to each of them, as it was NMS's.

Each mission loads its own map, collision map and creature placements (`MAPS/LEVn.*`, `LEVELn.BMF`, `LEVELnC.BIN`), its own briefing art and its own creatures, all on the disc. NMS's July code loaded only Mission 1's creatures (`LEVEL1/`), so missions 2 to 9 drew only the creatures Mission 1 also has. Their art was one step short of the game. `GRAPHICS/LEVEL2` to `LEVEL9` hold each creature as `.PSX` image and `.TXT` frame table, and the `.SPR` the loader reads is that `.TXT` compiled (NMS's `GRAPHICS/TXT2SPR.BAT`). `tools/x360_txt2spr.py` does the same step; it rebuilds 28 of Mission 1's 30 tables byte for byte. A creature's number in `LEVELn.BMF` is its name's index in the map converter's name table (`GRAPHICS/MAPS/GLOBALS.H`, `fnames_ian`), which ties all 1220 placements to the names in the editor's text maps. `LOADDATA.C` now loads each mission's set the way it loads Mission 1's, connecting a name to art only where NMS's files tie them (the art is named for the creature, or the mission's folder redrew a Mission 1 creature with the same frame layout); the comment there lists the evidence and every creature left undrawn for want of a file (vines, lasers, the `s_lNcK` and test names, the names the converter did not know). The converter writes 0 for a name it does not know and NMS's code draws 0 as the tube, so a 0 is drawn as the tube only where the editor's map names a tube there. Mission 1 is unchanged.

**Creature logic (July 1996).** The PS1 tree ran NMS's creature logic of 27 February 1996: ten routines, bound to eight creatures, so nearly everything only played its animation. NMS's schedule for the PS1 (`SOURCE/SCHED.TXT`, 20 June) says "ENEMY MOVEMENT 30% NEED NEW ENEMY AI FROM PHIL" and "GENERAL AI 50% NEED TO IMPLEMENT PHILS CODE". The logic it waited for survives: the Saturn port's `INCLUDES/AI.DAT` of 17 July 1996 (74 routines) and the PC version's interpreter and creature table (`SOURCE/MAKEBACK/PROCESS.C`, 12 June). Both are in the PS1 build now (see the decision rows). What the creatures do, checked in the emulator on every mission:
