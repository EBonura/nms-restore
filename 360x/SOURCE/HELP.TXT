SPRITES
28 sprites with full background 64*96  320*240
22 4 sided polygons +back       64*96  320*240
12 4 polys when magnified by 2
22 4 sided polys rotated  i.e. took no extra time to rotate!
16 colour sprites are faster
MAX sprite size 256x256
MAX poly4  size 128*128
sprites can not be scaled,translucent,rotated or flipped!

Major sprite/poly (concept) Bug discovered.
The demos and the books lead you into a method whereby all sprites primatives are 
precreated. Then to print the sprite all you need to do is poke the x,y of the 
relevent sprite primitive and call print_sprite. Unfortunately, when I added the 
Z buffering routine, If a sprite is added to the list, only a pointer to its primitive
is added, therefore if you try the print the same frame twice at different coords
only the last coord will be used! Creating sprite primitives everytime you add a sprite
is a slow process(But saves memory). Therefore I have opted to Precreate all score
panel sprites(as sprites,FAST) and print them direct(not via Z buffer list). Then
all in game sprites are defined as polygons(slow by flipable,scalable,rotatable) and
its primitive created there and then (slower but saves memory, and its possible to
Z buffer!).
THEREFORE  Print_Sprite    -prints pre_chopped SPRITE primitives immediately
		  Print_Poly      -adds POLY definitions to a z buffered list, printed later
