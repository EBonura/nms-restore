# 360X's scene images (R2), read by tools/scenes.py (format in its header). RESTORE: PLATFORM.
# docs/DECISIONS.md, "Scene images": the base keeps every variable (each object's .data and .bss) and
# all code a screen in play can reach; an image changes only where NMS's flow already loads its
# screen's files from the CD (the front end to the briefing, game over or QUIT back to the menus).
#
# The region is shared by the three images and is as large as the largest, so the RAM the split
# gives back is the smaller of FRONT and MISSION: MISSION is only as large as it needs to be (at
# least FRONT), and every byte of it is read at the Load_Level switch.

# arrange: the per-game setting (owner, 2026-11-23). This: MISSION resident in the region (the EXE carries it, the
# program's row tells the core so), FRONT at the very bottom of the heap (`heap`: carried in the EXE with the boot
# code, which runs right above it, and moved up with it). NMS's 1319 KB block (JALLOC.C) fills from the top down, and
# no screen or mission reaches FRONT: X360_TEST_HEAP over the nine missions, the lowest use is Mission 1's, 57,584 B
# above the block's base, FRONT ends 38,920 B above it (sector padded): 18,664 B to spare against the 8 KB the game
# asks for (docs/DECISIONS.md, the heap block). So FRONT is resident, the table is never read, and neither a
# briefing nor a QUIT (nor a game over, not run) reads anything the 1996 game did not (df8934c: QUIT to the menu 171 and 171,
# 171 and 171 here; NOTES-R3). The region is MISSION's 55,296 B. Before (11-24 night): FRONT above the boot code,
# reached by Mission 1, a volatile overlay read again at every QUIT: 210 the first time, 197 later.
# overlap (the shim's): FRONT and MISSION share the region, a read at every briefing too (+31). resident with FRONT
# in the region: no read at a switch, but the room goes to -19,268 B (maxmalloc, MAIN.C:51, would have to shrink).
# region: offset 0x7c0 puts MISSION's code where the x360-mission window's I-cache refill stalls match df8934c's
# (gate frontend, polls 2850..3400: 4.66M cycles, df8934c 4.71M; offset 0 5.96M, 0x800 4.82M, 0x840 8.71M, 0xa00
# 8.84M: a cliff just above 0x800). Harness speed at 0x7c0: 629,129 cycles a frame (df8934c 629,139; offset 0 639,558).
core
arrange resident
region 0x1000 0x7c0

# Boot-only code, not a scene (PLAN.md "Splash: one mechanism"): the splash (the SDK's, with the PSX Archive credit) and the film player, which
# only the start of the game uses. The EXE carries it; it runs at the start of the heap, which the game
# fills from the top down (JALLOC.C), as psyq-boot.ld's overlay did. No read before the splash.
image 3 BOOT boot
layer .boot_only .boot_only.* .text.FmvPlay .text.FmvMemoryBytes .text.*psx_fmv* .rodata.*psx_fmv* .bss.*psx_fmv*
layer .text.PsxSplash .text.*psx_splash* .rodata.*psx_splash*
entry PsxSplash FmvPlay FmvMemoryBytes

# The front end (the EXE carries it too, so the first screen needs no read): language, title and attract loop, main menu with the memory card, planet select,
# high-score entry.
image 1 FRONT heap
objects LANGUAGE TITLE SHIPDEMO HIGH CREDITS OPTIONS PLANETS
# LOADSAVE's strings stay in the base: please_w[] (LOADSAVE.C:59) points at them and Loading_Message
# (GENERAL.C:1447) prints it under every load, the mission's included.
code LOADSAVE
entry Select_Language Title_Screen Ship_Description High_Scores Display_Credits Game_Options Show_Planets Warp_To_Planet Check_High_Score

# The mission: briefing, the mission, status: the code only a mission runs (the scroller, controls,
# weapons, panel, level and map loaders). LEVEL.C and FIRE.C are built with -ffunction-sections so that
# Init_Newgame (the front-end flow calls it, MAIN.C) and Reset_Weapon_Ammo (MAIN.C calls it at power-on)
# stay in the base. PROCESS, SPRITE2 and PARTICLE stay in the base: the front end's star fields use
# PARTICLE, which calls SPRITE2.
image 2 MISSION
except LEVEL Init_Newgame
except FIRE Reset_Weapon_Ammo
objects CONTROL SCROLLER LOADDATA PANEL
entry Load_Level Exit_Level
# MAIN.C's mission loop (MAIN.C:220-395) calls the mission's functions directly; it runs only after
# Load_Level has loaded MISSION, and leaves it only through Check_High_Score or Game_Options (FRONT).
allow MAIN MISSION
