# psyq: the Psy-Q compatibility layer (v0)

NMS's games call Sony's Psy-Q libraries. This folder replaces the part of them QD Up and 360X need, on the PSoXide SDK, so the 1996 C can be rebuilt and run as NMS wrote it. Nothing here comes from Sony: no code, headers, libraries or documentation. Each function was written from how NMS's code uses it, from the hardware's documented behaviour (GPU commands, DMA, the controller protocol, the BIOS event numbers) and, where it mattered, from what NMS's 1996 build observably does in the emulator. No third-party SDK or libc is used.

- `include/`: the C headers the games include (`libgpu.h`, `libgs.h`, `libetc.h`, `kernel.h`, `libsn.h`, `ctrller.h`, `padequ.h`, `libgte.h`, `libsnd.h`, `libcd.h`, `cardio.h`, `sys/types.h`, `sys/file.h`, `stdio.h`, `stdlib.h`, `string.h`, `math.h`, `libmath.h`; `libspu.h`, `except.h`, `r3000.h`, `asm.h`, `sys/errno.h` exist and declare nothing). Every function they declare is defined in the library.
- `src/`: the library, Rust `no_std`, C ABI, built into `build/psyq/libpsyq.a` with psx-rt (the runtime and `_start`), psx-io, psx-gpu, psx-pad, psx-vram, psx-font, psx-gte, psx-spu and psx-mc.
- `psyq.ld`: the link (the SDK's `sdk/psoxide.ld` adapted for GNU ld), RAM size a parameter: 8 MB like NMS's dev kit or 2 MB. The stack reserve is a parameter too (`--defsym=STACK_RESERVE_OVERRIDE`, the SDK script's hook, 32 KB unless given).
- Scene images (tools/scenes.py, `360x/scenes.txt`, `qdup/scenes.txt`): a disc build links its images' script before `psyq.ld`; the images share one region after `.data` and are not in the EXE. `src/core_shim.rs` (C header `include/psx_core_shim.h`) is the one seam to the SDK's resident scene core: every sector the layer reads, loading an image, the handoff block. `src/scenes.rs` is what a wrapped entry calls. `src/boot.rs` is `__core_boot`, the first instruction: the stack top under the core's window.
- `build.sh`: clones the SDK sparsely into `build/psoxide` at a pinned commit of `origin/main` (the `rev=` line, 6bfe478ff0e0 at the time of writing; `PSOXIDE_REV` overrides it) and builds the library with the SDK's guest flags (`-Cpanic=immediate-abort -Zfmt-debug=none`) and without `host-tty` (`PSYQ_DEBUG=1` turns it on, a diagnostic build). `check-boot.sh` checks a boot-only link; `../psx-gate.toml` is the layer's file for the SDK's architecture gate.

## Build and run

```sh
qdup/build.sh                      # build/qdup/qdup.exe, linked for 8 MB (also builds the layer)
qdup/build.sh retail               # linked for 2 MB, files over the PC link
qdup/disc.sh                       # build/qdup-cd/qdup.cue + .bin: 2 MB, files from the CD
360x/build.sh                      # build/360x/360x.exe, 8 MB, -O2 (X360_OPT, X360_O0 change it)
360x/build.sh retail               # linked for 2 MB, files over the PC link
360x/disc.sh                       # build/360x-cd/360x.cue + .bin: 2 MB, files from the CD (360X.DAT)
tests/psyq-snd/build.sh && tests/psyq-snd/check.py
tests/psyq-libm/build.sh && tests/psyq-libm/check.py
python3 tools/qdup_run.py rebuild OUT --press "690:left:36,1090:cross:500,1130:down:180,1316:up:120" --shots 10
python3 tools/qdup_run.py cd OUT --press "500:start:10,650:up:6,710:up:6,770:right:6,1250:cross:6" --watch PlayType --shots 50
python3 tools/qdup_run.py 96 OUT --press "700:start,900:cross:30,1900:left:60,2300:cross:500,2340:down:180,2530:up:120" --shots 10
```

360X: `tools/x360_run.py 96|rebuild|cd OUT --press ... --shots N --watch NAME...` runs NMS's July 1996 MAIN.CPE (retail emulator) or the rebuild (dev kit emulator) on a fresh copy of the 1996 tree served over the PC link from its root, or the disc image (retail emulator, no PC link), logging watched variables (`NAME+OFFSET` for a field) every route tick; `tools/x360_match.py` pairs two runs' frames by watched state and counts differing pixels per phase. Start at route ticks 400, 1000, 1500, 2100, 3000 and 3400 takes either build from the language select through the title, the options menu, the planet select, the zoom to the planet and the briefing into Mission 1. Right held 5 ticks at 1850 + 14k (k = 0 to N-1) on the planet select picks mission N+1 instead (`tools/x360_run.py cd` reaches every one of the nine).

`qdup_run.py` runs the dev kit emulator headless on a fresh copy of the 1996 data folder (the game writes `TABLES/POTTERS/USTABLE.CSH` over the PC link) and logs `frames`, `game_frames`, `active_page`, `cue_angle`, `event_flag`, `mouse_ydiff` and `ball[0]` x, y, vx every route tick to `OUT/vars.csv`. `tools/shots_side_by_side.py` puts two runs' screenshots side by side, with a tick shift. `qdup_run.py cd` boots the disc (one disc, both views) in the retail emulator; the second example goes through the option screen (Start at the title, up twice to the players icon, right to change it, Start icon, then Cross again on the choice screen's 3D TABLE) into a game; the choice is read nowhere in NMS's files, so it is a two-player game. The rebuild examples above predate the option screen, which now comes before the table.

The game is compiled from cleaned copies (DOS `^Z` removed, lower-case names, `\` to `/` in `#include` lines) with GCC 14 `-std=gnu89 -fpermissive -O0 -G0 -fcommon -msoft-float`, `-Dmain=nms_main` (psx-rt calls the layer's `main`, which calls the game's). NMS's assembler (`CODE.S`, `ESCHER.S`, `SGL.S`) is rewritten into GNU syntax by `tools/asmpsx2gas` (Rust) at build time; `tools/asm_check.py` compares the result with the 1996 `POOL.CPE` word for word (relocated fields masked).

## Implemented

GPU (`gpu.rs`): `ResetGraph` (0 full reset, else command reset), `SetGraphDebug`, `SetVideoMode`, `GetVideoMode`, `SetDispMask`, `GetODE` (GPUSTAT bit 31: 1 while the odd lines of a 480-line picture are on show, 0 for the even ones and in the vertical blank), `SetDefDrawEnv`, `SetDefDispEnv`, `PutDrawEnv` (draw mode, texture window, area, offset, background fill), `PutDispEnv` (mode, ranges, start), `ClearOTagR` (DMA 6, CPU fallback), `ClearOTag`, `DrawOTag` (psx-gpu's linked-list walk, returns at once), `DrawPrim`, `DrawSync`, `LoadImage` (FIFO, odd pixel counts), `StoreImage`, `MoveImage`, `ClearImage`, `SetDrawMode`, `AddPrim`, `AddPrims`, `CatPrim`, `TermPrim`, `SetSprt`, `SetSprt8`, `SetSprt16`, `SetTile`, `SetLineF2`, `SetPolyF4`, `SetPolyFT4`, `SetSemiTrans`, `SetShadeTex`; the primitive structs and the `set*`/`get*` macros in `libgpu.h`. `SetDefDrawEnv` leaves `dfe` 0 for every height, as QD Up's 1996 build has it in its 320x480 option screen's DRAWENVs (read from its RAM): the background fill and the backdrop sprites (DR_MODE dfe 0) then skip the same field.

Debug font (`font.rs`): `FntLoad` (psx-font's 8x8 public-domain VGA font at the given VRAM page, CLUT 128 lines below), `FntOpen`, `SetDumpFnt`, `FntPrint`, `FntFlush`.

Kernel (`kernel.rs`): `ResetCallback`, `VSync` (0, n, 1, -1), `VSyncCallback`, `OpenEvent`, `CloseEvent`, `EnableEvent`, `DisableEvent`, `TestEvent`, `EnterCriticalSection`, `ExitCriticalSection`, `StartRCnt`, `StopRCnt`, `VSyncField` (not Psy-Q's: the next VBlank whose count has the parity asked, then on past the blank, 58 + 12 PAL or 20 + 12 NTSC lines on root counter 2; QD Up's 480-line screens draw one field a pass with it, `GFX.C` `display_screen`), `InitPAD`, `StartPAD`, `StopPAD`, `ChangeClearPAD`. One VBlank hook of psx-rt's dispatcher (`sdk/docs/INTERRUPTS.md`) does, at every VBlank and in interrupt context like the BIOS: poll the controller in port 1 (`psx_pad::Controllers::digital()`) into the `InitPAD` buffer, then call every enabled `RCntCNT3` event handler opened with `EvMdINTR` and the `VSyncCallback` function. `DrawSyncCallback` attaches the dispatcher's DMA source. The layer has no exception wrapper, vector write or stack of its own; the hook, the C callbacks and the DrawSync callback run on the dispatcher's 400 bytes (see docs/DECISIONS.md for the depths). `GoodData`, `GetType` and the `PAD_*` bits are header macros.

CD (`cd.rs`): `CdInit`, `CdSearchFile` (ISO 9660 path walk from the volume descriptor), `CdControl`/`CdControlB` (Setloc, SeekL, SeekP set the next read's position; Setmode, Pause, Stop, Nop accepted), `CdRead`, `CdReadSync`, `CdSync`, `CdIntToPos`, `CdPosToInt`, `CdReadyCallback` (kept, never called). Reads are blocking, on the SDK's polled `SectorReader` (SetLoc, SeekL, SetMode, ReadN, Pause per read). `CdSearchFile` keeps the last directory sector it read, so a game that looks its files up one by one seeks once per file, not twice (QD Up's option screen is ready at route tick 399 from the disc instead of 1383).

Movie playback (`fmv.rs`, not a Psy-Q library): `FmvMemoryBytes` and `FmvPlay`, a C entry over the PSoXide SDK's `psx-fmv` player (STR video from a root file of the disc, 15-bit, skip by a pad button; `psyq/include/psxfmv.h`). 360X's disc build plays its intro film with it. In 360X's disc build it is part of the BOOT scene image, gone once the front end's image is loaded: play films first. While it plays it holds the drive as the core's stream client.

Boot splash (`splash.rs`, not a Psy-Q library): `PsxSplash(line)`, a C entry over the SDK's `psx-splash` (`show_with_partner`, with the PSX Archive logo and "in collaboration with PSX Archive"), the standard studio splash every PSoXide game opens with (`psyq/include/psxsplash.h`). Both games call it once at boot with "Rebuilt with PSoXide". It takes over the GPU (320 by 240), reads the skip button through the pad buffer the game gave `InitPAD` (`kernel.rs`, `pad1_buttons`), and leaves a black frame; the caller sets its screen up again. In the disc builds it is the BOOT scene image, like the film player.

PMD models (`pmd.rs`, QD Up's option screen): the 16 `RotPMD_*`. The layout was read from the model files in the 1996 data (`MODELS/PMD/*.PMD`) and MODELS.C's walk: header (ID 42h, primitive and shared-vertex section offsets, object count), groups (type in the high half, packet count in the low half), per packet two filled-in GPU primitives (one per display buffer, `id`) then the vertices (shared types: byte offsets into the SVECTOR section). Corners from the GTE (RTPT, RTPS for quads), back faces skipped when `backc` is set (NCLIP <= 0), linked at the average depth cut to `otlen` bits. Every model in the data uses the shared-vertex flat and Gouraud triangles; the other types follow the same rules unexercised. Against the 1996 build (patched to call `Enter_Main_Options`) at the same camera angle the players screen differs in 692 of 153,600 pixels: the head model's one-pixel outline and the icon's animation frame.

PC link (`pcdrv.rs`): `PCinit`, `PCopen`, `PCcreat`, `PCread`, `PCwrite`, `PClseek`, `PCclose` (`BREAK 0x101..0x107`, arguments in a1..a3, v0 = 0 and v1 = result, else -1), `pollhost` (nothing to do without a debugger).

C library (`libc.rs`): `strlen`, `strcpy`, `strncpy`, `strcat`, `strcmp`, `strncmp`, `strchr`, `abs`, `labs`, `rand`, `srand`, `atoi`, `atol`, `strtol`, `strtod`, `atof`, `itoa`, `printf` (debug console), `sprintf`, `puts`, `putchar`. `memcpy`, `memset`, `memcmp` are psx-rt's, `memmove` and the soft-float arithmetic (`__adddf3` and the rest) are Rust's compiler-builtins.

Maths (`libm.rs`, written here): `sqrt`, `sin`, `cos`, `tan`, `atan`, `atan2`, `asin`, `acos`, `hypot`, `fabs`, `floor`, `ceil`, `fmod`.

Geometry (`gte.rs`): `InitGeom` (the 1996 GTE defaults: ZSF3 341, ZSF4 256, H 1000, DQA -4194, DQB 1400000h), `SetGeomOffset`, `SetGeomScreen`, `ReadGeomScreen`, `SetBackColor`, `SetFarColor`, `SetDQA`, `SetDQB`, `SetRotMatrix`, `SetTransMatrix`, `SetLightMatrix`, `SetColorMatrix`, `RotMatrix`, `ScaleMatrix`, `TransMatrix`, `MulMatrix`, `MulMatrix2`, `ApplyMatrixLV`, `TransposeMatrix`, `SquareRoot0`, with the 1996 roundings: `SquareRoot0` reads a table of floor(512 sqrt(m)) (not exact: sqrt(25000000) = 4990), `RotMatrix`'s sine is the rounded quarter sine with the second and fourth quarters mirrored one step off, `ApplyMatrixLV` shifts the high and low 15 bits separately. All three tables are generated from those rules and equal the 1996 ones.

Extended graphics (`gs.rs`, 360X): `GsInitGraph`, `GsDefDispBuff`, `GsSwapDispBuff`, `GsGetActiveBuff`, `GsSetWorkBase`, `GsClearOt`, `GsDrawOt`, `GsInit3D` (origin mid-screen, GTE offset mode), `GsSortFastSprite`, `GsSortSprite` (rotation and scale through the GTE, flips), `GsSortLine`, `GsSortGLine`, `GsGetTimInfo`, `GsInitCoordinate2`, `GsGetLw`, `GsGetLs`, `GsSetLsMatrix`, `GsSetLightMatrix`, `GsSetRefView2` (and `GsSetRefView` the same), `GsSetProjection`, `GsSetNearClip`, `GsSetFlatLight`, `GsSetAmbient`, `GsSetLightMode`, `GsSetFogParam`, `GsMapModelingData`, `GsLinkObject2`, `GsLinkObject4` (writes run lengths into the TMD as the 1996 library does), `GsSortObject4` for lit flat textured triangles with and without fog (the planets); `LoadTPage`, `GetTPage`. `DrawSyncCallback` (`gpu.rs`) is called from the DMA interrupt at the end of a `DrawOTag` walk (the kernel wrapper now also takes DMA interrupts), deferred while the foreground writes to the GPU; `GsClearOt` waits for it (360X's Interupt_GPU_Stuff frees its last sprite image there). `PutDispEnv` sets the TV area and mode as the 1996 library does (start 608 + 10 per screen.x unit, line 16 or 19 on PAL plus screen.y, 240 lines by default, 400-wide mode up to 400).

Sound (`snd.rs`, 360X): `SsInit`, `SsSetTableSize`, `SsSetTickMode`, `SsStart`, `SsEnd`, `SsSetMVol`, `SsSetMono`, `SsSetStereo`, `SsVabOpenHead` (what playing needs is read into the layer's own tables: 360X resets its heap at every screen while a bank stays open), `SsVabTransBody` (waveforms to sound RAM from 1010h), `SsVabTransBodyPartly` (the same body in pieces, in order; vabid when complete, -2 before), `SsVabClose`, `SsUtKeyOn` (voice registers written at the next tick, as in 1996; pitch by the 1996 note2pitch2 rule and a generated table equal to its), `SsUtKeyOff`, `SsUtAllKeyOff`, `SsSeqOpen` (checks "pQES"; the song is copied when it fits the layer's 4 KB), `SsSeqPlay`, `SsSeqStop`, `SsSeqClose`, `SsSeqSetVol`, `SsSeqCalledTbyT` (the tick: SsUtKeyOn's voices, then the songs). SEQ playback follows what NMS's March 1996 build of 360X (`NMS.zip NMS/360WORK/MAIN.CPE`, OPTPA.SEQ on OPTIONS.VAB through Sony's libsnd) does in the emulator: resolution x 10^6 / (tempo x 50) ticks a call on a PAL display (60 otherwise), the events due played before time moves on, a song played for ever restarting within the call its end comes due, each tone of the program whose key range holds the note on the lowest-numbered voice that is silent (else the lowest keyed off), voice volume x^2 x 3FFFh / 127^2 with x = velocity x channel volume / 127, full volume on both sides at the centre pan. `tests/psyq-snd/check_seq.py` runs both: 594 of the 1996 build's 618 voice register changes in 48 s are matched by the layer with the same volume, pitch and start address within one vertical blank (the 1996 build plays an event that falls exactly on a call boundary right after a call that played one a call later; the layer plays it at that boundary). Of the other 24, 18 are a rewrite of the nine channel-4 voices' volumes to 531/585 (left/right) that the 1996 library makes 41 calls before each restart, where OPTPA has no event; the layer does not do it. The last 6 were not matched; a register watch sampled at 60 Hz misses a key-on that sets a voice's registers to what they already were (2 of the 6 are that) or that a second key-on on the same voice overwrites before the next sample. Loudness envelope correlation 0.985, level ratio 1.02. Not played (360X's songs have none): controllers other than 7 and 10, pitch bend, loop markers. The song's, program's, tone's and bank's volumes below 127, and SsUtKeyOn's, which no 1996 build shows, multiply into x.

Memory card (`card.rs`, on psx-mc's SIO0 transport, `HardwareCard`): `InitCARD`, `StartCARD`, `StopCARD`, `_bu_init` (nothing to set up), `_card_info`, `_card_load`, `_card_read`, `_card_write`, `_card_clear`, `_new_card`, and the BIOS file calls on "bu00:" and "bu10:": `open` (with `O_CREAT|(blocks<<16)` it makes a file; names match with '?' and '*' as the BIOS's did), `read`, `write` (from the file's position, any length), `close`, `format`, `delete`. Each call does its frame transactions before it returns, with the VBlank controller poll paused (same port). The driver calls deliver their event before returning: `_card_info`/`_card_load` on `SwCARD`, the others on `HwCARD`; `EvSpIOE` done (for `_card_load`: formatted), `EvSpNEW` unformatted, `EvSpTIMOUT` no card, `EvSpERROR` a card that answers wrongly. A "new card" is never reported. Files use the card's standard directory (the layout psx-mc's `Card` writes), with the bytes the game writes, its own "SC" title frame first. 360X saves its high score table to "bu00:360X*SAVE" (one block) and loads it back; tested in the emulator with `--memcard` (the game then also finds a card in port 2) and with `--no-memcard`.

Also `malloc` (in order from the end of the program, never freed), `free` (does nothing, says so), `strrchr`, `bzero`; `rand`'s seed starts at 0 as in the 1996 builds (it is in their .bss).

## Stubs (print `psyq: STUB name` once on the debug console)

`WaitEvent`, `GsSortObject2` and `GsSortObject4` for TMD types other than lit flat textured triangles (360X links them, never draws them), `free`, `printf`'s floating-point conversions. Port 2 is never polled (QD Up does not read it; its buffer says no controller). Root counters count nothing. The boot and the shot below reach no stub.

## Checked against the 1996 build

All in the dev kit emulator, 1996 `POOL.CPE` against the rebuild, same data.

- Boot: the rebuild loads the same files in the same order (`gfx/front.tga`, `cosine.tab`, `potterus.esh`, `ballscue.esh`, the missing `//POTMEN//char01.raw` twice, `ustable.bmp`, writes `ustable.csh`). Title screen and the Potters table with the overlay match; the rebuild reaches the table loop at route tick 335, the 1996 build at 1546.
- Controller masks: `padequ.h` matches the constants in the 1996 `get_pad` and `getkey` (disassembled).
- Overlay: same four lines, positions and values. The 1996 debug font has no lower case, so `FntPrint` text is shown in capitals as there.
- Aim and shot with matched game state: inputs are tick-based and NMS's controls accelerate per game-loop pass (`keyboard_frac`, `cue_position`). The rebuild's loop runs every 2.5 route ticks against the 1996 build's 4, so the same presses give a different angle and power. With left held 36 ticks (60 in 1996) both reach cue angle 2285, and with the up press 6 ticks after down is released (10 in 1996) both shots start at vx -2.613640. From there every ball state the rebuild's log shows before the first cushion (7 of the 1996 build's 11 physics states; the others fall between two route ticks) is bit-identical in x, y and vx (all 64 bits): GCC 14 with compiler-builtins' soft-float and this libm compute what Sony's compiler and libraries computed.
- First cushion: the 1996 build reads a garbage cushion point (y = 464.14, the `#endif break;` bug fixed in `COMMON.C` earlier) and blows up to vx = -370 m/s, then stalls about 5000 ticks and ends with a scratch. The rebuild bounces (vx -1.62 to +1.81), the cue ball comes to rest at (0.228377, 0.320877), the turn passes to player 1 with BALL NOT HIT, BALL IN HAND.
- `libm`: `tests/psyq-libm` compares 204 results (200 maths, 4 atof) with the host's libm: at most 2 ulps (atan, atan2), `atof` exact on its four inputs.
- NMS's assembler: all 15 global functions of `CODE.S`, `ESCHER.S` and `SGL.S` assemble to the 1996 build's words except one instruction of `get_ram_available` (`ori` in the surviving source, `subu` in the 1996 build; same result for RAM sizes up to 2 GB).
- Load-delay hazards (`hazard-scan` of the SDK (psoxide-hazard), which the build runs on the linked program): none in the layer or GCC's code; one in NMS's `E_Load` (`lw s6` in the `jr ra` delay slot), as in 1996.

## Not checked or not matching

- QD Up display position: was about 6 lines higher than the 1996 build's on the 480-line title; `PutDispEnv` now follows the 1996 library (see above), not rechecked on QD Up's title. The 256-line table view lines up.
- Loop rate: the 1996 build in this emulator runs 139k instructions per route tick using 1.17M bus cycles (the rebuild 254k on 571k). Why the 1996 build's cycles per instruction are so high there is not known; it makes its loop slower, which matters because the controls are per-loop.

## Open problems

1. Optimisation: the -O1/-O2 jump to 0x61 was `ESCHER.S` `E_Load` returning without giving back its 12 bytes of stack (fixed, with `PlaceObjects`' swapped `move zero,t7`). -O1 plays as -O0. The -O2 cue bug noted earlier (Left held, cue not turning) no longer reproduces. At 9deed79 and on the qdup-play branch, dev kit and disc builds, 2D and 3D, Left held 36 ticks turns the cue from 1025 to 2285 at -O2 as at -O0; its cause was not found. The build uses -O0, as NMS's makefile did, except FIXBALL.C and FIXMATH.C (-O2, as the physics tests build them).
2. 2 MB: fits since the game runs FIXBALL.C (fixed-point tables): static data ends at 0x8010FD88 in the disc build, the heap peaks at 774,736 bytes (in game, `steves_memory` plus the parsed `ustable.bmp`; the title's `front.tga` needs 614 KB), the stack at about 15.5 KB, leaving 193 KB between them.
3. Port 2's controller is not implemented.
4. 360X at -O2 needs `-fno-toplevel-reorder` (its font tables share one end marker across three arrays).
5. 360X on 2 MB: done. MAIN.C called Initialise_Malloc twice, each a malloc of 1664 KB (maxmalloc 2048-384), and never used the first block; the first call is commented out and maxmalloc is 2048-704 (1344 KB). The program ends at 0x8009A7B0 with the memory card code (0x800969A8 before), leaving 86 KB between the heap block and the stack top. The 1996 build is linked for 8 MB (_ramsize 800000h); on a 2 MB console its second block lies above 2 MB, mirrored onto low RAM.
